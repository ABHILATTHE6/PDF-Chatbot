# Contributing to PDF Chatbot

Thank you for contributing.

## Development principles

- Keep changes focused and easy to review.
- Prefer small, meaningful commits.
- Do not commit secrets, API keys, credentials, or private documents.
- Add tests when changing core behavior.
- Update documentation when behavior or setup changes.

## Suggested workflow

1. Create a feature branch.
2. Make the change.
3. Run formatting, linting, and tests locally.
4. Update documentation if required.
5. Open a pull request with a clear description of the problem and solution.

## Commit messages

Use concise, action-oriented messages, for example:

```text
feat: add PDF text extraction pipeline
fix: handle empty PDF pages
refactor: separate retrieval service
```

## Pull requests

A good pull request should explain:

- What changed
- Why it changed
- How it was tested
- Any limitations or follow-up work

For user-facing changes, include screenshots or a short demonstration when practical.
